# 动力学网格与伴随计算修改记录（2026-05-29）

## 修改目标

本次修改的核心目标是把 beta/CLUTCH 计算链路中的几何网格来源、裂变矩阵、通量统计、伴随源和 response-weighted importance 统一到同一套物理和数据约定下。

重点原则：

- 几何仍由 OpenMC 原有 XML 读入流程建立，不为 beta 单独解析 `geometry.xml`。
- beta、flux、fission matrix、transfer function、adjoint flux 使用同一个 `SharedMeshGrid`。
- 所有 HDF5 文件写出统一的 `grid_shape`、`grid_lower_left`、`grid_upper_right`、`grid_pitch`。
- 网格不一致时立即报错，避免静默使用错误空间对应关系。

## 当前计算流程

1. OpenMC 初始化阶段读取 `materials.xml`、`geometry.xml`、`settings.xml`，或读取单个 `model.xml`。
2. `settings.xml` 中的 `<kinetics_mesh>` 控制动力学共享网格：

   ```xml
   <kinetics_mesh>
     <pitch>1.0</pitch>
     <auto_bounds>true</auto_bounds>
     <lower_left>-10 -10 -10</lower_left>
     <upper_right>10 10 10</upper_right>
   </kinetics_mesh>
   ```

3. `auto_bounds=true` 时，`SharedMeshGrid` 从根 universe 的 bounding box 获取几何范围；若几何边界无限且提供了手动 bounds，则回退到 `settings.xml` 中的 `lower_left/upper_right`。
4. `auto_bounds=false` 时，必须显式提供 `lower_left/upper_right`。
5. 初始化时只创建一次 `SharedMeshGrid`，随后共享给：
   - `FissionMatrix`
   - `GreenFunctionMesh`
   - `FluxMesh`
   - `BetaEffective`
6. 非活跃代末尾生成并归一化裂变矩阵，计算伴随源 `adjoint_source`。
7. 模拟结束时输出 transfer function、adjoint flux、flux mesh，并执行 beta effective 计算。

## 终端输出约定

网格创建后会在终端输出几何网格划分信息：

- `shape`
- `pitch`
- `cells`
- `bounds_source`
- `lower_left`
- `upper_right`

其中 `bounds_source` 用来区分网格范围来源：

- `XML geometry bounding box (read from geometry/model XML)`：来自 XML 几何的自动 bounding box。
- `manual bounds from settings.xml (auto_bounds=false)`：用户在 `settings.xml` 中手动指定。
- `manual bounds from settings.xml (geometry XML bounds infinite)`：尝试自动取 XML 几何边界，但几何无界，因此回退到手动 bounds。

## 理论检查与修正

### 1. 通量统计

原问题：

- 原实现按粒子移动后的终点位置给 mesh cell 记账。
- 如果一个飞行段跨越多个网格单元，整段径迹长度会被错误计入终点所在 cell。
- HDF5 中的 `flux_mean` 更接近批平均 track length，而不是体积归一化后的通量。

修正：

- 新增 `FluxMesh::accumulate_track()`，按飞行段与网格边界的交点分段。
- 每个子段按 `weight * segment_length` 计入对应 cell。
- 输出 `flux_mean`、`flux_group_mean`、`get_flux()` 时除以 cell volume，符合 track-length flux estimator。

涉及文件：

- `include/openmc/flux_mesh.h`
- `src/flux_mesh.cpp`
- `src/particle.cpp`

### 2. Transfer function / Green function

原问题：

- transfer function 中保存的是每个源状态的总响应。
- 理论上 response-weighted importance 应使用条件响应，即每个源粒子在该源状态下产生的平均响应。

修正：

- 新增 `source_state_counts_`，记录每个 `source_state = source_cell * n_groups + source_group` 的源粒子数。
- 输出每个 `source_state` 的 transfer response 时除以对应 `source_state_counts_`。
- 额外写出 `source_counts_per_state`。
- 若某个源状态存在响应但没有源计数，直接报错。

涉及文件：

- `include/openmc/greenfunction_mesh.h`
- `src/greenfunction_mesh.cpp`

### 3. 裂变矩阵伴随源

原问题：

- 原伴随源迭代形式实际是前向传播：

  ```text
  q(j) = sum_s M_norm[s,j] * I*(s)
  I*_new(j,g) = q(j) * chi_empirical(j,g)
  ```

- 这更接近右特征向量/前向源传播，不是伴随左特征向量。

修正：

- 改为转置算子的伴随迭代：

  ```text
  R(j) = sum_g chi_empirical(j,g) * I*(j,g)
  I*_new(s) = (1/k) * sum_j M_norm[s,j] * R(j)
  ```

- `compute_adjoint_source()` 和 `perform_adjoint_iteration()` 使用同一套转置迭代逻辑。
- 标量伴随源仍由分群伴随源按 cell 折叠得到，保持旧 HDF5 字段兼容。

涉及文件：

- `src/fission_matrix.cpp`

### 4. Adjoint flux 网格元数据

原问题：

- `AdjointFlux::compute_from_memory()` 会用 `origin + shape * pitch` 重新推导 `upper_right`。
- 当共享网格为了覆盖几何范围保留 margin 或实际 upper bound 不等于简单推导值时，`adjoint_flux.h5` 与 `flux_mesh.h5` 的 `grid_upper_right` 会不一致。

修正：

- `compute_from_files()` 在读入 transfer function 网格元数据后，将 `tf_grid.upper_right` 写回 `AdjointFlux`。
- `adjoint_flux.h5` 的 `grid_upper_right` 与 `transfer_function_data.h5` 保持一致。
- 这修复了类似以下错误：

  ```text
  Kinetics grid mismatch between flux_mesh.h5 and adjoint_flux.h5:
  grid_upper_right differs on axis 0.
  ```

涉及文件：

- `src/adjoint_flux.cpp`

### 5. Batch 初始化

原问题：

- `transfer_function_mesh->start_new_batch()` 在 batch 初始化中被调用两次。

修正：

- 移除重复调用，只保留一次 batch 管理入口。

涉及文件：

- `src/simulation.cpp`

## HDF5 网格元数据约定

以下文件应写出并使用同一套网格元数据：

- `flux_mesh.h5`
- `fission_matrix.h5`
- `transfer_function_data.h5`
- `adjoint_flux.h5`
- `beta_eff.h5`

统一字段：

```text
grid_shape
grid_lower_left
grid_upper_right
grid_pitch
```

beta 读取时以 `flux_mesh.h5` 为参考网格，并校验其他文件：

- shape 是否一致
- lower_left 是否一致
- upper_right 是否一致
- pitch 是否一致

任一字段不一致时直接报错。

## 现实性检查结论

当前网格获取逻辑是合理的：

- 对有限 CSG 几何，优先使用 OpenMC 已建立的根 universe bounding box，符合 XML 驱动几何的使用方式。
- 对无限几何，自动 bounding box 不具备物理有限范围，必须由用户显式给出 bounds；这比静默生成任意网格更安全。
- `FissionMatrix`、`FluxMesh`、`GreenFunctionMesh`、`BetaEffective` 使用同一维索引：

  ```text
  index = (ix * ny + iy) * nz + iz
  ```

- beta 的材料映射继续通过 OpenMC 几何查询采样点所属 cell/material，而不是手动几何表。

## 后续建议

建议使用实际 XML 输入重新运行一次完整流程，并检查：

- 终端输出的 `bounds_source` 是否符合预期。
- `flux_mesh.h5`、`transfer_function_data.h5`、`fission_matrix.h5`、`adjoint_flux.h5` 的网格元数据是否完全一致。

- 非立方网格下同一空间点在 flux、fission、beta 中是否映射到同一 cell index。
